# Removing Duplicates with DISTINCT

Our `buku` table has 12 rows, but only a handful of unique **categories** (Fiction, Non-Fiction, Self-Help, Technology, Finance). If you want to know what categories exist in the store — without duplicates — use `DISTINCT`.

## Basic DISTINCT

```sql
-- Without DISTINCT: the Fiksi category appears repeatedly (once per book)
SELECT kategori FROM buku;
```

```sql
-- With DISTINCT: each category appears only once
SELECT DISTINCT kategori FROM buku;
```

## DISTINCT on Multiple Columns

When `DISTINCT` is used with more than one column, it treats a row as "duplicate" only if the **entire combination of columns** matches exactly:

```sql
-- Unique combinations of (kategori, tahun_terbit)
SELECT DISTINCT kategori, tahun_terbit FROM buku;
```

Two rows with `kategori = 'Fiksi'` but different `tahun_terbit` are **not** considered duplicates — because the combination differs.

:::warning
`DISTINCT` is always placed right after `SELECT`, not before each column name:
```sql
SELECT DISTINCT kategori, penulis FROM buku;   -- correct
SELECT DISTINCT kategori, DISTINCT penulis FROM buku;  -- ERROR
```
:::

## DISTINCT vs GROUP BY

`DISTINCT` is similar to `GROUP BY`, which we'll learn in **Unit 3** — both group unique values together. The difference is that `GROUP BY` is usually paired with an aggregate function like `COUNT()` to count how many members are in each group, while `DISTINCT` simply removes duplicates without counting anything.

```sql
-- DISTINCT: just the list of unique categories
SELECT DISTINCT kategori FROM buku;

-- GROUP BY (later, in Unit 3): list of categories + count of books per category
-- SELECT kategori, COUNT(*) FROM buku GROUP BY kategori;
```
