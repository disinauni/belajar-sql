# Aliases & Advanced ON Conditions

You can already write basic `INNER JOIN`, `LEFT JOIN`, and `Self JOIN`. Now let's go deeper into a detail that often traps beginners: **where should an extra condition go — in `ON` or in `WHERE`?**

## ON Conditions With Multiple Requirements

`ON` doesn't have to contain exactly one equality condition — you can combine more than one requirement with `AND`:

```sql
-- Only join to loans that are STILL ACTIVE (not yet returned)
SELECT anggota.nama, peminjaman.tanggal_pinjam
FROM anggota
LEFT JOIN peminjaman
  ON anggota.id = peminjaman.anggota_id
  AND peminjaman.tanggal_kembali IS NULL;
```

## The Trap: ON vs WHERE on a LEFT JOIN

This is the important part. Compare the following two queries — they look similar at a glance, but produce **different** results:

```sql
-- Version A: the tanggal_kembali condition is in ON
SELECT anggota.nama, peminjaman.tanggal_pinjam
FROM anggota
LEFT JOIN peminjaman
  ON anggota.id = peminjaman.anggota_id AND peminjaman.tanggal_kembali IS NULL;
```

```sql
-- Version B: the tanggal_kembali condition moved to WHERE
SELECT anggota.nama, peminjaman.tanggal_pinjam
FROM anggota
LEFT JOIN peminjaman ON anggota.id = peminjaman.anggota_id
WHERE peminjaman.tanggal_kembali IS NULL;
```

Take Citra as an example: she borrowed one book once, but already returned it (so she has no active loan).

- **Version A** shows Citra with the loan columns as `NULL` — correct, since she genuinely has nothing borrowed **right now**.
- **Version B** loses Citra entirely from the result! Because `WHERE` is evaluated **after** the LEFT JOIN completes, Citra's row (whose tanggal_kembali holds an actual date, not NULL) gets filtered out by `WHERE peminjaman.tanggal_kembali IS NULL` — even though the original intent was to show ALL members.

<img src="/images/inner-vs-left-join.svg" alt="A condition in ON vs WHERE has a different effect on a LEFT JOIN" width="100%" />

:::warning
Placing a condition about the right table in `WHERE` (instead of `ON`) on a `LEFT JOIN` **accidentally turns it into something like an INNER JOIN** — because `WHERE` discards rows whose right-side columns are NULL, but that NULL is exactly what you wanted to preserve from the LEFT JOIN. Rule of thumb: a condition about "does this pair match" belongs in `ON`; a condition filtering the final result belongs in `WHERE`.
:::

## When WHERE Is Still Safe

If the condition is about the **left** table (not the right one), putting it in `WHERE` is fine, since the left table always appears in full anyway:

```sql
-- Safe: kelas is in the left table (anggota), doesn't affect LEFT JOIN's behavior
SELECT anggota.nama, peminjaman.tanggal_pinjam
FROM anggota
LEFT JOIN peminjaman ON anggota.id = peminjaman.anggota_id
WHERE anggota.kelas = '10A';
```

## Summary

| Concept | Example |
|---------|---------|
| ON with multiple conditions | `ON a.id = b.a_id AND b.column IS NULL` |
| Condition in ON (LEFT JOIN) | Preserves every left-table row |
| Condition in WHERE (LEFT JOIN) | Can accidentally discard left rows — like an INNER JOIN |
| Safe in WHERE | A condition only about the left table |
