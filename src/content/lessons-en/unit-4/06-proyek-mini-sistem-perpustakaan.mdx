# Mini Project: Library System

Congratulations on reaching the end of Unit 4! You can now work with databases made up of **many interrelated tables** — just like a real information system. Let's solve a few real reports for a school library administrator.

## The JOIN Toolkit You've Mastered

| Technique | Use |
|-----------|-----|
| `INNER JOIN` | Combine rows with a match in both tables |
| `LEFT JOIN` | Keep every left-table row, even without a match |
| JOIN 3+ tables | Chain several JOIN clauses in sequence |
| Self JOIN | Join a table with itself (2 aliases) |
| Condition in ON vs WHERE | ON for match conditions, WHERE for final filtering |

## Case Study: Most Popular Books Report

**"Which book titles are borrowed the most? Show the title and loan count, sorted highest first, only books borrowed at least once"**

```sql
SELECT buku.judul, COUNT(*) AS jumlah_dipinjam
FROM peminjaman
INNER JOIN buku ON peminjaman.buku_id = buku.id
GROUP BY buku.judul
ORDER BY jumlah_dipinjam DESC;
```

**"Which books have NEVER been borrowed at all?"**

```sql
SELECT buku.judul
FROM buku
LEFT JOIN peminjaman ON buku.id = peminjaman.buku_id
WHERE peminjaman.id IS NULL;
```

## Reflection: What You've Mastered

| Concept | Function |
|---------|----------|
| Normalization & Foreign Key | Splitting data into separate tables, linked by FK |
| `INNER JOIN` | Only rows matched in both tables |
| `LEFT JOIN` | Every left row, NULL if no match |
| Multi-table JOIN | Chaining several `JOIN` clauses |
| Self JOIN | A table JOINed with itself, two aliases |
| ON vs WHERE | ON for match conditions, WHERE for result filtering |
