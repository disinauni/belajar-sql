# LEFT JOIN

The `INNER JOIN` from the previous lesson "hides" members who've never borrowed a book — they have no match, so they don't appear. But what if your question is actually **"which members have never borrowed?"** — you need `LEFT JOIN`.

## Basic LEFT JOIN

```sql
SELECT anggota.nama, peminjaman.tanggal_pinjam
FROM anggota
LEFT JOIN peminjaman ON anggota.id = peminjaman.anggota_id;
```

`LEFT JOIN` returns **every row from the left table** (`anggota`), even if there's no match in the right table (`peminjaman`). For members without a loan, the `peminjaman` columns will be filled with `NULL`.

<img src="/images/inner-vs-left-join.svg" alt="LEFT JOIN includes every left-table row, INNER JOIN only matches" width="100%" />

:::note
"Left" refers to the table written in `FROM`, and "right" to the table written after `LEFT JOIN`. `FROM anggota LEFT JOIN peminjaman` means anggota is the left table.
:::

## Finding "Unmatched" Rows

The `LEFT JOIN` + `WHERE ... IS NULL` combination is a classic pattern for finding left-table rows with **no match at all**:

```sql
-- Members who have never borrowed any book
SELECT anggota.nama
FROM anggota
LEFT JOIN peminjaman ON anggota.id = peminjaman.anggota_id
WHERE peminjaman.id IS NULL;
```

If `peminjaman.id` (which should always be filled in if there's a match) comes out `NULL`, that indicates this `anggota` row has **no match at all** in `peminjaman`.

## Books That Have Never Been Borrowed

The same pattern can be flipped to find books that have never been borrowed:

```sql
SELECT buku.judul
FROM buku
LEFT JOIN peminjaman ON buku.id = peminjaman.buku_id
WHERE peminjaman.id IS NULL;
```

## Books Currently Out (Not Yet Returned)

Remember the nullable `tanggal_kembali` column from an earlier lesson? This combination finds loans still active:

```sql
SELECT anggota.nama, buku.judul
FROM peminjaman
INNER JOIN anggota ON peminjaman.anggota_id = anggota.id
INNER JOIN buku ON peminjaman.buku_id = buku.id
WHERE peminjaman.tanggal_kembali IS NULL;
```

:::tip
Notice: `tanggal_kembali IS NULL` here is a different context from `peminjaman.id IS NULL` in the "find unmatched" pattern. The former checks the column's actual value (not yet returned), while the latter checks "absence of a JOIN match" (a column that should always exist, but is NULL because LEFT JOIN found no match).
:::

## Summary

| Concept | Example |
|---------|---------|
| Basic LEFT JOIN | `FROM a LEFT JOIN b ON a.id = b.a_id` |
| Every left row included | No match → right-side columns become NULL |
| Find unmatched rows | `LEFT JOIN ... WHERE b.id IS NULL` |
