# Self JOIN

Every JOIN we've learned so far combines **two different tables** (`anggota` with `peminjaman`, etc.). But sometimes a single table has a column that references **another row in that same table** — the classic case: an employee organizational structure and their manager.

## Example Schema: Employee & Manager

This lesson uses a new table dedicated to this topic:

```sql
CREATE TABLE pegawai (
  id INTEGER PRIMARY KEY,
  nama TEXT NOT NULL,
  atasan_id INTEGER REFERENCES pegawai(id)
);
```

| id | nama | atasan_id |
|----|------|-----------|
| 1 | Andi (Director) | *(NULL — no manager)* |
| 2 | Budi (Manager) | 1 |
| 3 | Citra (Manager) | 1 |
| 4 | Dedi (Staff) | 2 |
| 5 | Eka (Staff) | 2 |
| 6 | Fira (Staff) | 3 |

The `atasan_id` (manager_id) column references `id` in the **same** table — Budi (id 2) has a manager with id 1, i.e. Andi.

## Why We Need a Self JOIN

Without a JOIN, you can only see numbers: "employee id 2 has manager id 1" — meaningless. To display the **manager's name**, you need to join the `pegawai` table with itself.

## Self JOIN with Two Aliases

Since it's the same table, you **must** give each copy a different alias to distinguish their "role":

```sql
SELECT e.nama AS pegawai, m.nama AS atasan
FROM pegawai AS e
LEFT JOIN pegawai AS m ON e.atasan_id = m.id;
```

- `e` (employee) — the table copy for the "employee" role
- `m` (manager) — the table copy for the "manager" role
- `ON e.atasan_id = m.id` — links the employee's atasan_id with the id in the "manager" copy

`LEFT JOIN` is used (not `INNER JOIN`) so Andi (whose `atasan_id` is NULL, no manager) still appears in the result.

:::note
Without aliases, `SELECT pegawai.nama FROM pegawai JOIN pegawai ON ...` would confuse SQLite — it wouldn't know which `pegawai.nama` you mean, since there are two copies of the `pegawai` table in the same query. The `AS e` and `AS m` aliases remove this ambiguity.
:::

## Finding All Reports of a Manager

```sql
-- All staff whose manager is Budi
SELECT e.nama AS bawahan
FROM pegawai AS e
INNER JOIN pegawai AS m ON e.atasan_id = m.id
WHERE m.nama = 'Budi (Manajer)';
```

:::tip
A Self JOIN always follows the same pattern: one table, two aliases, one `ON` linking the "child" column with the "parent" column on a different row of the same table.
:::

## Summary

| Concept | Example |
|---------|---------|
| Self JOIN | `FROM pegawai AS e JOIN pegawai AS m ON e.atasan_id = m.id` |
| When to use it | Data referencing other rows in the same table |
| Aliases required | To distinguish two "roles" of the same table |
