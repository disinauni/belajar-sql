# Tour of the SQL Playground

Time to try it yourself! Every interactive lesson in this course has a **playground** — an editor box where you write and run SQL queries.

## Playground Anatomy

<img src="/images/playground-anatomy.svg" alt="SQL playground anatomy: editor, run button, result panel" width="100%" />

The main parts are:

- **Query editor** — where you type SQL, with syntax highlighting
- **Run button (▶)** — executes the query you're currently writing
- **Reset button** — restores the query and data to their initial state
- **Result panel** — shows the query result as a table, or an error message if something's wrong

## Run Your First Query

Below is a real playground, already seeded with the `toko_buku` sample database. Try typing the following query (or use the one already provided), then click **Run**:

```sql
SELECT * FROM buku;
```

## Trying Reset

Now try changing the query above to this, then run it:

```sql
DELETE FROM buku WHERE kategori = 'Fiksi';
```

You'll see a message like **"N row(s) affected"** — meaning data was actually deleted from the currently-running database! Try running `SELECT * FROM buku;` again — the fiction books are gone.

:::warning
Don't panic — this isn't real data on any server. Click the **Reset** button and all data will return to its original state, since the database is rebuilt from scratch every time it's reset.
:::

## Reading Error Messages

This playground runs real SQLite, so the error messages you see are genuine SQLite error messages. Try running a misspelled query:

```sql
SELCT * FROM buku;
```

You'll see something like `near "SELCT": syntax error` — SQLite tells you exactly which word it didn't recognize.

:::tip
When you hit an error, read the message slowly. SQLite usually points to the word or punctuation causing the problem with the phrase "near ...".
:::
