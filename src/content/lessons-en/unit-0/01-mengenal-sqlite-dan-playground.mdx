# Meet SQLite & the Playground

There are many database "engines" in the real world: **MySQL**, **PostgreSQL**, **SQL Server**, **Oracle**, and **SQLite**. They all understand the SQL language, but they differ in how they run and where they "live".

## SQLite: A Database Without a Server

Most databases (MySQL, PostgreSQL, etc.) run as a separate **server** — a program that must be started and listened to over a network, usually on a different machine (a server).

**SQLite** is different. It's an **embedded** database — the entire database lives in a single small file, with no separate server needed, no complicated installation, no login process. Mobile apps, browsers, and even desktop applications widely use SQLite to store local data.

<img src="/images/sqlite-in-browser.svg" alt="SQLite running in the browser via WebAssembly" width="100%" />

:::note
SQLite is the most widely deployed database in the world — it's on nearly every Android/iOS phone, in browsers, and in millions of applications. Despite being "lite", it fully supports standard SQL.
:::

## A Playground That Runs in the Browser

In this course, we use a library called **sql.js** — a version of SQLite compiled to **WebAssembly (WASM)**, a format that lets non-JavaScript code run directly in the browser at near-native speed.

This means:

- **No installation** of any database on your computer
- **No server** — every query runs directly in the browser
- **No API key** or internet connection needed after the page loads
- Every time you click **Reset**, the database is rebuilt instantly

```sql
-- This query runs directly in your browser, not on any server
SELECT * FROM buku;
```

:::tip
Since everything runs in the browser, you can experiment as freely as you like — even trying `DELETE` or `DROP TABLE` — without fear of breaking anyone's data. Just click Reset to go back to the start.
:::

## Database, Table, and Query — Commonly Confused Terms

| Term | Definition | Analogy |
|------|------------|---------|
| **Database** | A container holding many tables | A filing cabinet |
| **Table** | A data structure of rows & columns | One folder inside the cabinet |
| **Query** | The SQL statement you write and run | A request to the archive clerk |

Throughout this course, we'll work with a single sample database called **`toko_buku`** (bookstore), containing a `buku` (books) table — so you can focus on learning SQL without worrying about a new schema every lesson.
