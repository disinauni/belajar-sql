# ALTER TABLE & DROP TABLE

Sometimes an existing table's structure needs to change — adding a new column, renaming it, or (in extreme cases) removing it entirely. `ALTER TABLE` and `DROP TABLE` are the DDL statements for this.

## Adding a Column with ALTER TABLE ADD COLUMN

```sql
CREATE TABLE buku (
  id INTEGER PRIMARY KEY,
  judul TEXT NOT NULL
);

ALTER TABLE buku ADD COLUMN rating REAL;

SELECT * FROM buku;
```

A table that already has data stays safe — existing rows get a `NULL` value for the new column, unless you add a `DEFAULT`:

```sql
ALTER TABLE buku ADD COLUMN stok INTEGER DEFAULT 0;
```

## Renaming a Table

```sql
ALTER TABLE buku RENAME TO koleksi_buku;
```

## Renaming a Column

```sql
ALTER TABLE koleksi_buku RENAME COLUMN judul TO judul_buku;
```

:::note
SQLite has historically supported only limited `ALTER TABLE` operations (`ADD COLUMN`, `RENAME TABLE`, `RENAME COLUMN`) compared to other RDBMSes like PostgreSQL, which can change a column's data type directly. For complex changes in SQLite, the common pattern is: create a new table with the desired structure, copy the data over, drop the old table, rename the new one.
:::

## DROP TABLE — Removing a Table Entirely

```sql
DROP TABLE koleksi_buku;
```

After this, the `koleksi_buku` table **along with all its data** is completely gone — not just its contents (like `DELETE FROM`), but its structure too.

:::warning
`DROP TABLE` cannot be undone. This is the most destructive statement in SQL — even more drastic than `DELETE` or `UPDATE` without `WHERE`, since it removes the table's definition too. In real production databases, `DROP TABLE` is usually restricted to administrators with a special approval process.
:::

## Summary

| Statement | Effect |
|-----------|--------|
| `ALTER TABLE ... ADD COLUMN` | Adds a new column to an existing table |
| `ALTER TABLE ... RENAME TO` | Renames a table |
| `ALTER TABLE ... RENAME COLUMN` | Renames a column |
| `DROP TABLE` | Permanently removes a table along with its structure |
