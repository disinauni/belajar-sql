# Constraints: PRIMARY KEY, FOREIGN KEY, etc.

A **constraint** is a rule attached to a table column to prevent invalid data from being stored. You've already been using some constraints since early in this course (`PRIMARY KEY`, `NOT NULL`, `REFERENCES`) — now let's see them all in full.

## Constraint Summary

| Constraint | Function |
|-----------|----------|
| `PRIMARY KEY` | Unique value, the main identity of each row |
| `FOREIGN KEY` / `REFERENCES` | References another table's Primary Key |
| `NOT NULL` | Column is required, cannot be NULL |
| `UNIQUE` | Value must differ from every other row |
| `DEFAULT` | Automatic value if not supplied during INSERT |
| `CHECK` | Value must satisfy a given condition |

## Full Example

```sql
CREATE TABLE anggota (
  id INTEGER PRIMARY KEY,
  nama TEXT NOT NULL,
  email TEXT UNIQUE,
  status TEXT DEFAULT 'aktif',
  umur INTEGER CHECK (umur >= 10)
);
```

Let's break down each constraint:
- `id INTEGER PRIMARY KEY` — every member must have a unique id
- `nama TEXT NOT NULL` — name is required
- `email TEXT UNIQUE` — two members can't share the same email (but it can be NULL if not filled in)
- `status TEXT DEFAULT 'aktif'` — if not supplied during INSERT, automatically fills with `'aktif'`
- `umur INTEGER CHECK (umur >= 10)` — SQLite rejects an `INSERT` with age under 10

## Seeing Constraints in Action

```sql
-- This will succeed — status defaults to 'aktif', email is unique
INSERT INTO anggota (id, nama, email, umur) VALUES (1, 'Dewi', 'dewi@email.com', 15);

-- This will FAIL — email already used by id 1 (violates UNIQUE)
INSERT INTO anggota (id, nama, email, umur) VALUES (2, 'Farhan', 'dewi@email.com', 16);

-- This will FAIL — age below 10 (violates CHECK)
INSERT INTO anggota (id, nama, email, umur) VALUES (3, 'Budi', 'budi@email.com', 8);
```

:::tip
Constraints are data "gatekeepers" — they reject data that violates a rule **before** it gets stored, so you don't need to manually validate data on every query. Design constraints from the start in `CREATE TABLE`, don't wait for invalid data to get in and clean it up later.
:::

## FOREIGN KEY as a Constraint

```sql
CREATE TABLE peminjaman (
  id INTEGER PRIMARY KEY,
  anggota_id INTEGER NOT NULL REFERENCES anggota(id),
  tanggal_pinjam TEXT NOT NULL
);
```

`REFERENCES anggota(id)` is shorthand for a `FOREIGN KEY` constraint — SQLite (if enabled) will reject an `INSERT` into `peminjaman` with an `anggota_id` that doesn't exist in the `anggota` table.

## Summary

| Constraint | Example |
|-----------|---------|
| `PRIMARY KEY` | `id INTEGER PRIMARY KEY` |
| `FOREIGN KEY` | `anggota_id INTEGER REFERENCES anggota(id)` |
| `NOT NULL` | `nama TEXT NOT NULL` |
| `UNIQUE` | `email TEXT UNIQUE` |
| `DEFAULT` | `status TEXT DEFAULT 'aktif'` |
| `CHECK` | `umur INTEGER CHECK (umur >= 10)` |
