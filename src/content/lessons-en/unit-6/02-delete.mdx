# Removing Data with DELETE

`DELETE` removes rows from a table — the last DML statement after `INSERT` and `UPDATE`.

## Basic DELETE

```sql
DELETE FROM buku WHERE id = 6;
```

The row with `id = 6` will be permanently gone from the currently-running database. Try `SELECT * FROM buku;` afterward — that row no longer exists.

## DELETE by Condition

```sql
-- Remove all books with 0 stock
DELETE FROM buku WHERE stok = 0;
```

```sql
-- Remove Finance category books priced under 100000
DELETE FROM buku WHERE kategori = 'Keuangan' AND harga < 100000;
```

Every `WHERE` technique from Units 1-2 (comparison operators, `AND`/`OR`, `IN`, `BETWEEN`, etc.) applies exactly the same way to `DELETE`.

## DANGER: DELETE Without WHERE

```sql
-- DANGER! This deletes ALL rows in the buku table — the table itself still exists, but empty
DELETE FROM buku;
```

:::warning
Just like `UPDATE`, `DELETE` **without `WHERE`** deletes **ALL rows** in the table. This is one of the most dangerous statements in SQL — always double-check your `WHERE`, and on a real database, consider running a `SELECT` with the same `WHERE` first to confirm the rows about to be deleted are really what you intend.
:::

## DELETE vs DROP TABLE

It's important not to confuse these two statements:

| Statement | Effect |
|-----------|--------|
| `DELETE FROM buku;` | Removes **all rows**, the `buku` table (its structure/schema) still exists, empty |
| `DROP TABLE buku;` | Removes **the table itself** entirely — both structure and all data are gone |

We'll cover `DROP TABLE` in more detail in the **ALTER TABLE & DROP TABLE** lesson.

:::tip
After `DELETE FROM buku;`, you can still `INSERT` new data into the `buku` table because its structure still exists. After `DROP TABLE buku;`, you'd need to `CREATE TABLE buku (...)` again from scratch before you can use it.
:::
