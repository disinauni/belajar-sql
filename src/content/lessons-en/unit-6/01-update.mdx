# Modifying Data with UPDATE

`UPDATE` changes column values on rows that **already exist** in a table — unlike `INSERT`, which adds new rows.

## Basic UPDATE

```sql
UPDATE buku
SET stok = 15
WHERE id = 1;
```

- **`UPDATE buku`** — the table to modify
- **`SET stok = 15`** — which column to change, and its new value
- **`WHERE id = 1`** — which row(s) are affected by this change

Try `SELECT * FROM buku WHERE id = 1;` after running the `UPDATE` above to see the change.

## Changing Multiple Columns at Once

```sql
UPDATE buku
SET harga = 75000, stok = 20
WHERE id = 1;
```

Separate each `column = value` with a comma inside a single `SET`.

## DANGER: UPDATE Without WHERE

```sql
-- DANGER! This sets stock to 0 for ALL rows in the table, not just one book
UPDATE buku SET stok = 0;
```

:::warning
`UPDATE` **without `WHERE`** changes **ALL rows** in the table, not just one. This is one of the most destructive mistakes in SQL — in the real world (not this playground), it can mean permanently losing production data. Always double-check your `WHERE` clause before running an `UPDATE`, especially on a real database.
:::

:::tip
Safe habit: before running an `UPDATE`, first run a `SELECT` with the same `WHERE` to see **exactly which rows** will be affected. If the `SELECT` result matches your expectation, only then change `SELECT *` into `UPDATE ... SET ...`.
:::

## UPDATE Affecting Multiple Rows by Condition

```sql
-- Raise the price by 10% for all Fiction category books
UPDATE buku
SET harga = harga * 1.1
WHERE kategori = 'Fiksi';
```

Notice `harga = harga * 1.1` — the new value can be computed from the same column's **old** value, not just a fixed value.

| Multiple columns | `SET harga = 75000, stok = 20` |
| Compute from old value | `SET harga = harga * 1.1` |
