# Creating Tables with CREATE TABLE

So far we've always worked with tables that were **already set up** for us. Now it's time to learn SQL's other side: designing your own table from scratch. This lesson's playground is **empty** — there's no table at all until you create one yourself!

## Basic CREATE TABLE

```sql
CREATE TABLE siswa (
  id INTEGER PRIMARY KEY,
  nama TEXT NOT NULL,
  nilai INTEGER
);
```

- **`CREATE TABLE siswa`** — the new table's name
- Each line in parentheses defines one column: its **name**, then its **data type**
- `PRIMARY KEY` and `NOT NULL` are *constraints* (rules) — covered in more detail in the next lesson

Once created, the `siswa` table is still **empty** — `CREATE TABLE` only defines the structure, it doesn't fill in any data.

## SQLite's Basic Data Types

| Type | Stores | Example |
|------|--------|---------|
| `INTEGER` | Whole numbers | `17`, `0`, `-5` |
| `REAL` | Decimal numbers | `3.14`, `72500.5` |
| `TEXT` | Text/strings | `'Budi'`, `'Fiksi'` |

```sql
CREATE TABLE produk (
  id INTEGER PRIMARY KEY,
  nama TEXT NOT NULL,
  harga REAL NOT NULL,
  stok INTEGER
);
```

:::note
SQLite actually uses a more flexible type system ("type affinity") than other RDBMSes like PostgreSQL/MySQL — it doesn't always enforce data types as strictly. But still declare data types correctly, since other RDBMSes are much stricter, and it's good practice that keeps your schema clear to anyone reading it.
:::

## Filling a New Table with INSERT

Once the table structure exists, you can `INSERT` right away as usual:

```sql
CREATE TABLE siswa (
  id INTEGER PRIMARY KEY,
  nama TEXT NOT NULL,
  nilai INTEGER
);

INSERT INTO siswa (id, nama, nilai) VALUES
  (1, 'Dewi', 88),
  (2, 'Farhan', 92);

SELECT * FROM siswa;
```

## Summary

| Concept | Example |
|---------|---------|
| Create a table | `CREATE TABLE name (column type, ...);` |
| Data types | `INTEGER`, `REAL`, `TEXT` |
| New table | Always empty until `INSERT`ed into |
| DDL vs DML | `CREATE TABLE` = DDL (structure), `INSERT`/`UPDATE`/`DELETE` = DML (data) |

Next: tightening data rules with **constraints** — `PRIMARY KEY`, `FOREIGN KEY`, `NOT NULL`, `UNIQUE`, `DEFAULT`, and `CHECK`.
