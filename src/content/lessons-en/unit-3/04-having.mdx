# Filtering Groups with HAVING

`WHERE` filters **raw rows** before grouping. But what if you want to filter based on the **aggregate result** — e.g. "show categories with more than 2 books"? `WHERE` can't do this, since `COUNT(*)` doesn't exist yet before grouping finishes. That's what `HAVING` is for.

## Basic HAVING

```sql
SELECT kategori, COUNT(*) AS jumlah
FROM buku
GROUP BY kategori
HAVING COUNT(*) > 1;
```

Only categories with more than 1 book show up — categories with exactly 1 book (Non-Fiksi, Keuangan) get filtered out.

<img src="/images/group-by-having.svg" alt="WHERE filters rows, HAVING filters group results" width="100%" />

## WHERE vs HAVING — The Fundamental Difference

| | `WHERE` | `HAVING` |
|---|---------|----------|
| Operates on | Raw rows, before grouping | Group results, after aggregation |
| Can use aggregate functions? | No | Yes |
| When evaluated | Before `GROUP BY` | After `GROUP BY` |

```sql
-- Logically WRONG: WHERE can't use COUNT(*)
SELECT kategori, COUNT(*) FROM buku WHERE COUNT(*) > 1 GROUP BY kategori;
```

```sql
-- CORRECT: HAVING is used to filter aggregate results
SELECT kategori, COUNT(*) FROM buku GROUP BY kategori HAVING COUNT(*) > 1;
```

## Combining WHERE and HAVING

Both can be used together — `WHERE` filters rows first, then grouping happens, then `HAVING` filters the group results:

```sql
-- Only books with stock > 0, grouped by category,
-- then show categories with average price above 70000
SELECT kategori, ROUND(AVG(harga), 0) AS rata_rata
FROM buku
WHERE stok > 0
GROUP BY kategori
HAVING AVG(harga) > 70000;
```

:::tip
An easy way to remember: **WHERE filters BEFORE grouping** (individual rows), **HAVING filters AFTER grouping** (aggregate results). If your condition involves `COUNT`/`SUM`/`AVG`/`MIN`/`MAX`, it belongs in `HAVING`, not `WHERE`.
:::

## Summary

| Concept | Example |
|---------|---------|
| Filter group result | `GROUP BY kategori HAVING COUNT(*) > 1` |
| WHERE + HAVING together | `WHERE stok > 0 GROUP BY kategori HAVING AVG(harga) > 70000` |
| Key rule | A condition with an aggregate function → `HAVING`, not `WHERE` |
