# EXISTS & NOT EXISTS

`EXISTS` is an operator that checks whether a subquery returns **at least one row** — it doesn't care about the row's contents, only whether it **exists or not**.

## Correlated Subqueries

Every subquery we've written so far stands alone — it can run independently of the outer query. `EXISTS` is usually paired with a **correlated subquery**: a subquery that references a column from the outer query within its condition.

```sql
SELECT nama
FROM anggota AS a
WHERE EXISTS (
  SELECT 1 FROM peminjaman AS p WHERE p.anggota_id = a.id
);
```

Notice `p.anggota_id = a.id` — this subquery references `a.id` from the outer table (`anggota AS a`). This subquery is **re-evaluated for every row** in the outer table: "does a peminjaman row exist with anggota_id equal to THIS member's id?"

:::note
`SELECT 1` inside an `EXISTS` subquery is a common convention — the number `1` there doesn't matter, since `EXISTS` only checks **whether a row exists**, not its value. You could just as well write `SELECT *` or `SELECT anggota_id`, the result is the same.
:::

## NOT EXISTS

```sql
-- Members who have never borrowed (no matching peminjaman row)
SELECT nama
FROM anggota AS a
WHERE NOT EXISTS (
  SELECT 1 FROM peminjaman AS p WHERE p.anggota_id = a.id
);
```

## EXISTS vs IN — When Do Results Differ?

For a simple case like this, `EXISTS` and `IN` produce the same result:

```sql
-- With IN (from the previous lesson)
SELECT nama FROM anggota WHERE id IN (SELECT anggota_id FROM peminjaman);

-- With EXISTS (equivalent)
SELECT nama FROM anggota AS a
WHERE EXISTS (SELECT 1 FROM peminjaman AS p WHERE p.anggota_id = a.id);
```

But `NOT EXISTS` is **safer** than `NOT IN` when the subquery could potentially contain `NULL` — `NOT EXISTS` doesn't have the NULL trap that `NOT IN` has. Because of this, many developers make `EXISTS`/`NOT EXISTS` their safer default habit.

:::tip
Rule of thumb: if you only need to know "does ANY related data exist", use `EXISTS`/`NOT EXISTS`. If you need to match against a concrete list of values, `IN` still works fine — as long as the column is guaranteed not to be NULL.
:::

## Summary

| Concept | Example |
|---------|---------|
| EXISTS | `WHERE EXISTS (SELECT 1 FROM p WHERE p.x = a.id)` |
| NOT EXISTS | `WHERE NOT EXISTS (...)` |
| Correlated subquery | A subquery referencing a column from the outer query |
| Safer than | `NOT IN` (no NULL trap) |
