# CTEs (WITH) & UNION

Two final techniques for this unit: **CTEs** to make subqueries more readable by naming them, and **UNION** to combine the results of two different queries into one.

## CTE — Common Table Expression

Nested subqueries (a subquery inside a subquery) can quickly become hard to read. A **CTE** lets you define a subquery **upfront**, give it a name, then use it like a regular table in the main query:

```sql
WITH buku_mahal AS (
  SELECT * FROM buku WHERE harga > 90000
)
SELECT judul, kategori FROM buku_mahal WHERE kategori = 'Teknologi';
```

Compare this to writing a nested subquery in `FROM`:

```sql
-- Version without a CTE — same result, but starts getting hard to read as logic grows more complex
SELECT judul, kategori
FROM (SELECT * FROM buku WHERE harga > 90000) AS buku_mahal
WHERE kategori = 'Teknologi';
```

For a simple query, both are equivalent. But a CTE becomes much more useful once you have **several** nested subqueries, or want to reuse the same subquery's result **more than once** within a single query.

## CTEs with Multiple Definitions

```sql
WITH
  ringkasan_kategori AS (
    SELECT kategori, AVG(harga) AS rata_rata FROM buku GROUP BY kategori
  ),
  kategori_mahal AS (
    SELECT kategori FROM ringkasan_kategori WHERE rata_rata > 85000
  )
SELECT judul, kategori FROM buku WHERE kategori IN (SELECT kategori FROM kategori_mahal);
```

## UNION — Combining Two Queries' Results

`UNION` combines the results of two (or more) `SELECT` queries into one list, and **removes duplicates** automatically:

```sql
-- Titles that are either very cheap OR very expensive
SELECT judul FROM buku WHERE harga < 60000
UNION
SELECT judul FROM buku WHERE harga > 110000;
```

:::warning
Both queries combined by `UNION` must have the **same number of columns**, with compatible data types. The result's column names follow the **first** query.
:::

## UNION ALL — Keeping Duplicates

If you know there won't be duplicates (or you actually want to keep them for efficiency/some purpose), use `UNION ALL` — it's faster since it skips the duplicate check:

```sql
SELECT judul, 'Murah' AS label FROM buku WHERE harga < 60000
UNION ALL
SELECT judul, 'Mahal' AS label FROM buku WHERE harga > 110000;
```

Adding a label column like `'Murah'`/`'Mahal'` (a fixed text value, not from a column) helps distinguish which query a row came from.

## Summary

| Concept | Example |
|---------|---------|
| CTE | `WITH name AS (SELECT ...) SELECT ... FROM name;` |
| Multiple CTEs | `WITH a AS (...), b AS (...) SELECT ...` |
| UNION | Combine + remove duplicates |
| UNION ALL | Combine + keep duplicates (faster) |
