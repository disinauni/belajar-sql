# Mini Project: Data Analysis

Congratulations on reaching the end of Unit 5! You now have a new way of thinking to answer complex questions: **breaking them into nested queries**, not just combining tables.

## The Toolkit You've Mastered

| Technique | Use |
|-----------|-----|
| Subquery in WHERE | Compare a row against an aggregate result |
| Subquery in SELECT/FROM | Show a comparison value, or process another query's result |
| `IN` + subquery | Match against another query's result list |
| `EXISTS`/`NOT EXISTS` | Check for related data existence (correlated subquery) |
| CTE (`WITH`) | Name a subquery for readability |
| `UNION`/`UNION ALL` | Combine two queries' results into one list |

## Case Study: Featured Categories Report

**"Which categories have an average price above the STORE'S OVERALL average, and what books are in those categories?"**

```sql
WITH rata_rata_toko AS (
  SELECT AVG(harga) AS nilai FROM buku
),
kategori_unggulan AS (
  SELECT kategori
  FROM buku
  GROUP BY kategori
  HAVING AVG(harga) > (SELECT nilai FROM rata_rata_toko)
)
SELECT judul, kategori, harga
FROM buku
WHERE kategori IN (SELECT kategori FROM kategori_unggulan)
ORDER BY kategori, harga DESC;
```

Notice how the CTE keeps this nested query readable step by step, instead of one giant deeply-nested subquery.

## Reflection: What You've Mastered

| Concept | When to Use |
|---------|--------------|
| Scalar subquery (WHERE/SELECT) | Compare against a single aggregate value |
| FROM subquery (derived table) | Further process another query's result |
| `IN`/`NOT IN` + subquery | Match against a list from another table |
| `EXISTS`/`NOT EXISTS` | Efficiently check for related data existence |
| CTE (`WITH`) | Name a complex subquery for readability |
| `UNION`/`UNION ALL` | Combine several queries' results into one list |
