# LIKE & Wildcards

`WHERE judul = 'Sapiens'` only finds an **exact** match. But what if you want to find every title **containing** the word "Cinta", without knowing the full title? That's what `LIKE` is for.

## The `%` Wildcard — Zero or More Characters

```sql
-- Titles that CONTAIN the word "Cinta" anywhere
SELECT judul FROM buku WHERE judul LIKE '%Cinta%';
```

```sql
-- Titles STARTING with the letter "B"
SELECT judul FROM buku WHERE judul LIKE 'B%';
```

```sql
-- Titles ENDING with the letter "a"
SELECT judul FROM buku WHERE judul LIKE '%a';
```

The `%` symbol means "here there can be zero characters, one character, or any number of characters at all".

## The `_` Wildcard — Exactly One Character

An underscore `_` matches **exactly one** character, no more, no less:

```sql
-- Categories with exactly 5 letters: "Fiksi" matches, "Teknologi" doesn't
SELECT judul, kategori FROM buku WHERE kategori LIKE '_____';
```

## NOT LIKE

```sql
-- Titles that do NOT contain the word "Cinta"
SELECT judul FROM buku WHERE judul NOT LIKE '%Cinta%';
```

## Combining Patterns

```sql
-- Starts with "A", ends with "a"
SELECT judul FROM buku WHERE judul LIKE 'A%a';
```

:::note
By default, `LIKE` in SQLite is **not case-sensitive** for ASCII letters — `LIKE '%cinta%'` and `LIKE '%Cinta%'` produce the same result.
:::

:::warning
`LIKE` without any wildcard behaves just like `=` — `WHERE judul LIKE 'Sapiens'` only matches "Sapiens" exactly. The `%`/`_` wildcards are what make LIKE useful for pattern searches.
:::

## Summary

| Pattern | Meaning | Example |
|---------|---------|---------|
| `'%word%'` | Contains "word" anywhere | `LIKE '%Cinta%'` |
| `'word%'` | Starts with "word" | `LIKE 'B%'` |
| `'%word'` | Ends with "word" | `LIKE '%a'` |
| `'_____'` | Exactly 5 characters | `LIKE '_____'` |
| `NOT LIKE` | The opposite of LIKE | `NOT LIKE '%Cinta%'` |
