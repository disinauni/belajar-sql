# Logical Operators: AND, OR, NOT

In Unit 1 you used `WHERE` with a single condition. But real questions often need **more than one requirement at once** — e.g. "Fiction books priced under 70000". That's where `AND`, `OR`, and `NOT` come in.

## AND — Both Conditions Must Be True

```sql
SELECT judul, kategori, harga
FROM buku
WHERE kategori = 'Fiksi' AND harga < 70000;
```

A row only appears if **both** conditions are satisfied. You can chain more than two conditions with repeated `AND`:

```sql
SELECT judul FROM buku
WHERE kategori = 'Fiksi' AND harga < 70000 AND stok > 0;
```

## OR — Either Condition Is Enough

```sql
SELECT judul, kategori
FROM buku
WHERE kategori = 'Teknologi' OR kategori = 'Keuangan';
```

A row appears if **at least one** of the conditions is satisfied.

:::warning
`AND`/`OR` are often confused with everyday language. "Show Fiction and Technology books" sounds like "AND" in casual speech, but it actually means "category = Fiction **OR** category = Technology" — since one row can't have two categories at once!
:::

## NOT — Inverting a Condition

```sql
SELECT judul, kategori
FROM buku
WHERE NOT kategori = 'Fiksi';
```

Equivalent to `WHERE kategori <> 'Fiksi'`. `NOT` is more useful when inverting a more complex condition:

```sql
SELECT judul FROM buku
WHERE NOT (kategori = 'Fiksi' AND harga > 80000);
```

## Evaluation Order & Parentheses

When `AND` and `OR` are combined, SQL evaluates `AND` **before** `OR` — the same way multiplication happens before addition in math.

```sql
-- Without parentheses: evaluated as (kategori = 'Fiksi') OR (kategori = 'Teknologi' AND harga < 60000)
SELECT judul FROM buku
WHERE kategori = 'Fiksi' OR kategori = 'Teknologi' AND harga < 60000;
```

If you mean something different, **always write explicit parentheses** — don't rely on implicit ordering:

```sql
-- Clearer: "category Fiksi OR Teknologi, AND priced under 60000"
SELECT judul FROM buku
WHERE (kategori = 'Fiksi' OR kategori = 'Teknologi') AND harga < 60000;
```

:::tip
Once your WHERE clause has more than one AND/OR, always add parentheses even if the default order is already correct — so anyone reading it (including future you) immediately understands the intent without recalling precedence rules.
:::

## Summary

| Operator | Meaning | Example |
|----------|---------|---------|
| `AND` | Both conditions must be true | `harga < 70000 AND stok > 0` |
| `OR` | Either condition is enough | `kategori = 'A' OR kategori = 'B'` |
| `NOT` | Inverts a condition | `NOT kategori = 'Fiksi'` |
| `(...)` | Groups conditions explicitly | `(A OR B) AND C` |
