# Menghilangkan Duplikat dengan DISTINCT

Tabel `buku` kita punya 12 baris, tapi hanya beberapa **kategori** unik (Fiksi, Non-Fiksi, Pengembangan Diri, Teknologi, Keuangan). Kalau kamu ingin tahu apa saja kategori yang ada — tanpa duplikat — pakai `DISTINCT`.

## DISTINCT Dasar

```sql
-- Tanpa DISTINCT: kategori Fiksi akan muncul berkali-kali (satu per buku)
SELECT kategori FROM buku;
```

```sql
-- Dengan DISTINCT: setiap kategori hanya muncul sekali
SELECT DISTINCT kategori FROM buku;
```

## DISTINCT pada Banyak Kolom

Ketika `DISTINCT` dipakai dengan lebih dari satu kolom, ia menganggap baris "duplikat" hanya jika **seluruh kombinasi kolom** itu sama persis:

```sql
-- Kombinasi (kategori, tahun_terbit) yang unik
SELECT DISTINCT kategori, tahun_terbit FROM buku;
```

Dua baris dengan `kategori = 'Fiksi'` tapi `tahun_terbit` berbeda **tidak** dianggap duplikat — karena kombinasinya beda.

:::warning
`DISTINCT` selalu diletakkan tepat setelah `SELECT`, bukan sebelum tiap nama kolom:
```sql
SELECT DISTINCT kategori, penulis FROM buku;   -- benar
SELECT DISTINCT kategori, DISTINCT penulis FROM buku;  -- ERROR
```
:::

## DISTINCT vs GROUP BY

`DISTINCT` mirip dengan `GROUP BY` yang akan kita pelajari di **Unit 3** — keduanya sama-sama mengelompokkan nilai unik. Bedanya, `GROUP BY` biasanya dipakai bersama fungsi agregat seperti `COUNT()` untuk menghitung berapa banyak anggota tiap kelompok, sedangkan `DISTINCT` sekadar menghilangkan duplikat tanpa menghitung apapun.

```sql
-- DISTINCT: hanya daftar kategori unik
SELECT DISTINCT kategori FROM buku;

-- GROUP BY (nanti di Unit 3): daftar kategori + jumlah buku per kategori
-- SELECT kategori, COUNT(*) FROM buku GROUP BY kategori;
```

## Ringkasan

| Konsep | Contoh |
|--------|--------|
| Nilai unik satu kolom | `SELECT DISTINCT kategori FROM buku;` |
| Kombinasi unik banyak kolom | `SELECT DISTINCT kategori, tahun_terbit FROM buku;` |
| Terkait dengan | `GROUP BY` (dipelajari di Unit 3) |
