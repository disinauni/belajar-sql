# LIKE & Wildcard

`WHERE judul = 'Sapiens'` hanya menemukan kecocokan **persis**. Tapi bagaimana kalau kamu ingin mencari semua judul yang **mengandung** kata "Cinta", tanpa tahu judul lengkapnya? Di situlah `LIKE` dipakai.

## Wildcard `%` — Nol atau Lebih Karakter

```sql
-- Judul yang MENGANDUNG kata "Cinta" di mana saja
SELECT judul FROM buku WHERE judul LIKE '%Cinta%';
```

```sql
-- Judul yang DIAWALI huruf "B"
SELECT judul FROM buku WHERE judul LIKE 'B%';
```

```sql
-- Judul yang DIAKHIRI huruf "a"
SELECT judul FROM buku WHERE judul LIKE '%a';
```

Tanda `%` berarti "di sini boleh ada nol karakter, satu karakter, atau berapapun karakter apa saja".

## Wildcard `_` — Tepat Satu Karakter

Garis bawah `_` mencocokkan **tepat satu** karakter, tidak lebih tidak kurang:

```sql
-- Kategori dengan tepat 5 huruf: "Fiksi" cocok, "Teknologi" tidak
SELECT judul, kategori FROM buku WHERE kategori LIKE '_____';
```

## NOT LIKE

```sql
-- Judul yang TIDAK mengandung kata "Cinta"
SELECT judul FROM buku WHERE judul NOT LIKE '%Cinta%';
```

## Kombinasi Pola

```sql
-- Diawali "A", diakhiri "a" (contoh: "Ayat-Ayat Cinta", "Atomic..." kalau berakhiran a)
SELECT judul FROM buku WHERE judul LIKE 'A%a';
```

:::note
Secara default, `LIKE` di SQLite **tidak case-sensitive** untuk huruf ASCII — `LIKE '%cinta%'` dan `LIKE '%Cinta%'` menghasilkan hasil yang sama.
:::

:::warning
`LIKE` tanpa wildcard sama saja dengan `=` — `WHERE judul LIKE 'Sapiens'` hanya cocok persis "Sapiens". Wildcard `%`/`_` itulah yang membuat LIKE berguna untuk pencarian pola.
:::

## Ringkasan

| Pola | Arti | Contoh |
|------|------|--------|
| `'%kata%'` | Mengandung "kata" di mana saja | `LIKE '%Cinta%'` |
| `'kata%'` | Diawali "kata" | `LIKE 'B%'` |
| `'%kata'` | Diakhiri "kata" | `LIKE '%a'` |
| `'_____'` | Tepat 5 karakter | `LIKE '_____'` |
| `NOT LIKE` | Kebalikan dari LIKE | `NOT LIKE '%Cinta%'` |

Selanjutnya: memeriksa banyak kemungkinan nilai sekaligus dengan **IN**.
