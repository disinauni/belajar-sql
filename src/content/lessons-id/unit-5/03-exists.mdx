# EXISTS & NOT EXISTS

`EXISTS` adalah operator yang memeriksa apakah sebuah subquery mengembalikan **setidaknya satu baris** — ia tidak peduli isi barisnya, hanya peduli **ada atau tidaknya**.

## Subquery Berkorelasi (Correlated Subquery)

Semua subquery yang kita tulis sebelumnya berdiri sendiri — bisa dijalankan terpisah dari query luar. `EXISTS` biasanya dipakai dengan **subquery berkorelasi**: subquery yang merujuk ke kolom dari query luar di dalam kondisinya.

```sql
SELECT nama
FROM anggota AS a
WHERE EXISTS (
  SELECT 1 FROM peminjaman AS p WHERE p.anggota_id = a.id
);
```

Perhatikan `p.anggota_id = a.id` — subquery ini merujuk ke `a.id` dari tabel luar (`anggota AS a`). Subquery ini **dievaluasi ulang untuk setiap baris** di tabel luar: "apakah ada baris peminjaman dengan anggota_id sama dengan id anggota INI?"

:::note
`SELECT 1` di dalam subquery `EXISTS` adalah konvensi umum — angka `1` di situ tidak penting isinya, karena `EXISTS` hanya mengecek **keberadaan baris**, bukan nilainya. Kamu bisa saja menulis `SELECT *` atau `SELECT anggota_id`, hasilnya sama saja.
:::

## NOT EXISTS

```sql
-- Anggota yang belum pernah meminjam (tidak ada baris peminjaman yang cocok)
SELECT nama
FROM anggota AS a
WHERE NOT EXISTS (
  SELECT 1 FROM peminjaman AS p WHERE p.anggota_id = a.id
);
```

## EXISTS vs IN — Kapan Beda Hasilnya?

Untuk kasus sederhana seperti ini, `EXISTS` dan `IN` menghasilkan hasil yang sama:

```sql
-- Dengan IN (dari lesson sebelumnya)
SELECT nama FROM anggota WHERE id IN (SELECT anggota_id FROM peminjaman);

-- Dengan EXISTS (setara)
SELECT nama FROM anggota AS a
WHERE EXISTS (SELECT 1 FROM peminjaman AS p WHERE p.anggota_id = a.id);
```

Tapi `NOT EXISTS` **lebih aman** daripada `NOT IN` ketika subquery berpotensi mengandung `NULL` — `NOT EXISTS` tidak punya masalah jebakan NULL yang dimiliki `NOT IN`. Karena itu, banyak yang membiasakan diri memakai `EXISTS`/`NOT EXISTS` sebagai kebiasaan default yang lebih aman.

:::tip
Aturan praktis: kalau kamu hanya perlu tahu "apakah ADA data terkait", pakai `EXISTS`/`NOT EXISTS`. Kalau kamu perlu mencocokkan dengan daftar nilai konkret, `IN` masih cocok — asal kolomnya dijamin tidak NULL.
:::

## Ringkasan

| Konsep | Contoh |
|--------|--------|
| EXISTS | `WHERE EXISTS (SELECT 1 FROM p WHERE p.x = a.id)` |
| NOT EXISTS | `WHERE NOT EXISTS (...)` |
| Subquery berkorelasi | Subquery yang merujuk kolom dari query luar |
| Lebih aman dari | `NOT IN` (tidak punya jebakan NULL) |

Selanjutnya: memberi nama pada subquery dengan **CTE (WITH)**, dan menggabungkan hasil dua query dengan **UNION**.
