# Proyek Mini: Analisis Data

Selamat sampai di akhir Unit 5! Kamu sekarang punya cara berpikir baru untuk menjawab pertanyaan kompleks: **memecahnya jadi query bertingkat**, bukan cuma menggabungkan tabel.

## Perangkat yang Sudah Kamu Kuasai

| Teknik | Kegunaan |
|--------|----------|
| Subquery di WHERE | Bandingkan baris dengan hasil agregat |
| Subquery di SELECT/FROM | Tampilkan nilai pembanding, atau proses hasil query lain |
| `IN` + subquery | Cocokkan dengan daftar hasil query lain |
| `EXISTS`/`NOT EXISTS` | Cek keberadaan data terkait (subquery berkorelasi) |
| CTE (`WITH`) | Beri nama pada subquery agar lebih mudah dibaca |
| `UNION`/`UNION ALL` | Gabungkan hasil dua query jadi satu daftar |

## Studi Kasus: Laporan Kategori Unggulan

**"Kategori mana saja yang rata-rata harganya di atas rata-rata KESELURUHAN toko, dan buku apa saja di kategori itu?"**

```sql
WITH rata_rata_toko AS (
  SELECT AVG(harga) AS nilai FROM buku
),
kategori_unggulan AS (
  SELECT kategori
  FROM buku
  GROUP BY kategori
  HAVING AVG(harga) > (SELECT nilai FROM rata_rata_toko)
)
SELECT judul, kategori, harga
FROM buku
WHERE kategori IN (SELECT kategori FROM kategori_unggulan)
ORDER BY kategori, harga DESC;
```

Perhatikan bagaimana CTE membuat query bertingkat ini tetap terbaca selangkah demi selangkah, alih-alih satu subquery raksasa yang bersarang.

## Refleksi: Apa yang Sudah Kamu Kuasai

| Konsep | Kapan Dipakai |
|--------|-----------------|
| Subquery scalar (WHERE/SELECT) | Bandingkan dengan satu nilai agregat |
| Subquery FROM (derived table) | Proses hasil query lain lebih lanjut |
| `IN`/`NOT IN` + subquery | Cocokkan dengan daftar dari tabel lain |
| `EXISTS`/`NOT EXISTS` | Cek keberadaan data terkait secara efisien |
| CTE (`WITH`) | Beri nama subquery kompleks agar terbaca |
| `UNION`/`UNION ALL` | Gabungkan hasil beberapa query jadi satu daftar |
