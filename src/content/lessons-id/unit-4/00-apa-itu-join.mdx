# Apa itu JOIN & Foreign Key?

Sejauh ini kita hanya bekerja dengan **satu tabel**: `buku`. Tapi database dunia nyata nyaris selalu terdiri dari **banyak tabel yang saling berhubungan**. Mulai unit ini, kita memakai database contoh baru: **`perpustakaan`** (sistem peminjaman buku perpustakaan sekolah).

## Kenapa Data Dipecah ke Banyak Tabel?

Bayangkan kalau semua data peminjaman buku disimpan dalam **satu tabel raksasa**:

| peminjam | kelas | judul_buku | penulis | tanggal_pinjam |
|----------|-------|-----------|---------|-----------------|
| Dewi | 10A | Laskar Pelangi | Andrea Hirata | 2026-05-01 |
| Dewi | 10A | Sapiens | Yuval Noah Harari | 2026-05-15 |

Nama "Dewi" dan kelasnya "10A" **terduplikasi** setiap kali dia meminjam buku baru. Kalau Dewi pindah kelas, kamu harus mengubah banyak baris sekaligus — rawan data jadi tidak konsisten.

**Normalisasi** adalah praktik memecah data seperti ini ke tabel-tabel terpisah, masing-masing menyimpan satu jenis informasi, supaya tidak ada duplikasi.

## Skema `perpustakaan`

<img src="/images/multi-table-join-flow.svg" alt="Skema tiga tabel: anggota, buku, peminjaman" width="100%" />

Database `perpustakaan` punya 3 tabel:

**`anggota`** — data anggota perpustakaan
| id | nama | kelas |
|----|------|-------|
| 1 | Dewi | 10A |
| 2 | Farhan | 10B |
| ... | ... | ... |

**`buku`** — koleksi buku perpustakaan (tabel baru, terpisah dari `buku` di database `toko_buku` sebelumnya)
| id | judul | penulis | stok |
|----|-------|---------|------|
| 1 | Laskar Pelangi | Andrea Hirata | 3 |
| ... | ... | ... | ... |

**`peminjaman`** — catatan transaksi peminjaman, menghubungkan `anggota` dan `buku`
| id | anggota_id | buku_id | tanggal_pinjam | tanggal_kembali |
|----|-----------|---------|-----------------|-------------------|
| 1 | 1 | 1 | 2026-05-01 | 2026-05-10 |
| 2 | 1 | 3 | 2026-05-15 | *(NULL — belum dikembalikan)* |

## Foreign Key — Penghubung Antar Tabel

Kolom `anggota_id` dan `buku_id` di tabel `peminjaman` disebut **Foreign Key** — kolom yang merujuk ke Primary Key di tabel lain. `anggota_id = 1` di baris peminjaman berarti "peminjam ini adalah anggota dengan id 1" (yaitu Dewi).

```sql
CREATE TABLE peminjaman (
  id INTEGER PRIMARY KEY,
  anggota_id INTEGER REFERENCES anggota(id),
  buku_id INTEGER REFERENCES buku(id),
  tanggal_pinjam TEXT NOT NULL,
  tanggal_kembali TEXT
);
```

Kata kunci `REFERENCES anggota(id)` mendeklarasikan hubungan Foreign Key ini secara eksplisit.

:::note
Tanpa `JOIN`, tabel `peminjaman` sendirian hanya berisi angka-angka ID yang tidak bermakna bagi manusia (`anggota_id = 1`, `buku_id = 3`). `JOIN` adalah cara menggabungkan tabel-tabel ini kembali supaya kamu bisa melihat "Dewi meminjam Sapiens", bukan cuma "1 meminjam 3".
:::

:::tip
Coba jalankan `SELECT * FROM peminjaman;` di playground lesson ini — kamu akan melihat kenapa tabel ini sendirian kurang berguna tanpa JOIN. Kita akan perbaiki itu di lesson berikutnya!
:::

## Ringkasan

| Istilah | Arti |
|---------|------|
| Normalisasi | Memecah data ke banyak tabel untuk menghindari duplikasi |
| Foreign Key | Kolom yang merujuk ke Primary Key tabel lain |
| `perpustakaan` | Database contoh baru: `anggota`, `buku`, `peminjaman` |
| `REFERENCES` | Kata kunci mendeklarasikan Foreign Key di CREATE TABLE |

Selanjutnya: menggabungkan tabel-tabel ini kembali dengan **INNER JOIN**.
