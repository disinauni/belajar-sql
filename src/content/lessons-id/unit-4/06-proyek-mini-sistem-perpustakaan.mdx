# Proyek Mini: Sistem Perpustakaan

Selamat sampai di akhir Unit 4! Kamu sekarang bisa bekerja dengan database yang terdiri dari **banyak tabel berhubungan** — persis seperti sistem informasi sungguhan. Mari selesaikan beberapa laporan nyata untuk pengelola perpustakaan sekolah.

## Perangkat JOIN yang Sudah Kamu Kuasai

| Teknik | Kegunaan |
|--------|----------|
| `INNER JOIN` | Gabungkan baris yang punya pasangan di kedua tabel |
| `LEFT JOIN` | Pertahankan semua baris tabel kiri, meski tanpa pasangan |
| JOIN 3+ tabel | Rangkai beberapa klausa JOIN berturut-turut |
| Self JOIN | Gabungkan tabel dengan dirinya sendiri (2 alias) |
| Syarat di ON vs WHERE | ON untuk syarat pasangan, WHERE untuk syarat hasil akhir |

## Studi Kasus: Laporan Buku Terpopuler

**"Judul buku apa saja yang paling banyak dipinjam? Tampilkan judul dan jumlah peminjaman, urutkan dari yang terbanyak, hanya buku yang pernah dipinjam minimal 1 kali"**

```sql
SELECT buku.judul, COUNT(*) AS jumlah_dipinjam
FROM peminjaman
INNER JOIN buku ON peminjaman.buku_id = buku.id
GROUP BY buku.judul
ORDER BY jumlah_dipinjam DESC;
```

**"Buku apa saja yang BELUM PERNAH dipinjam sama sekali?"**

```sql
SELECT buku.judul
FROM buku
LEFT JOIN peminjaman ON buku.id = peminjaman.buku_id
WHERE peminjaman.id IS NULL;
```

## Refleksi: Apa yang Sudah Kamu Kuasai

| Konsep | Fungsi |
|--------|--------|
| Normalisasi & Foreign Key | Memecah data ke tabel terpisah, dihubungkan dengan FK |
| `INNER JOIN` | Hanya baris berpasangan di kedua tabel |
| `LEFT JOIN` | Semua baris kiri, NULL jika tak ada pasangan |
| JOIN banyak tabel | Rangkai beberapa `JOIN` berturut-turut |
| Self JOIN | Tabel di-JOIN dengan dirinya sendiri, dua alias |
| ON vs WHERE | ON untuk syarat pasangan, WHERE untuk syarat hasil |
