# Constraint: PRIMARY KEY, FOREIGN KEY, dan Lainnya

**Constraint** adalah aturan yang ditempelkan pada kolom tabel untuk mencegah data yang tidak valid tersimpan. Kamu sudah memakai beberapa constraint sejak awal kursus ini (`PRIMARY KEY`, `NOT NULL`, `REFERENCES`) — sekarang mari lihat semuanya secara lengkap.

## Ringkasan Constraint

| Constraint | Fungsi |
|-----------|--------|
| `PRIMARY KEY` | Nilai unik, identitas utama tiap baris |
| `FOREIGN KEY` / `REFERENCES` | Merujuk ke Primary Key tabel lain |
| `NOT NULL` | Kolom wajib diisi, tidak boleh NULL |
| `UNIQUE` | Nilai tidak boleh sama dengan baris lain |
| `DEFAULT` | Nilai otomatis jika tidak diisi saat INSERT |
| `CHECK` | Nilai harus memenuhi kondisi tertentu |

## Contoh Lengkap

```sql
CREATE TABLE anggota (
  id INTEGER PRIMARY KEY,
  nama TEXT NOT NULL,
  email TEXT UNIQUE,
  status TEXT DEFAULT 'aktif',
  umur INTEGER CHECK (umur >= 10)
);
```

Mari bedah tiap constraint:
- `id INTEGER PRIMARY KEY` — setiap anggota harus punya id unik
- `nama TEXT NOT NULL` — nama wajib diisi
- `email TEXT UNIQUE` — dua anggota tidak boleh punya email yang sama (tapi boleh NULL kalau belum diisi)
- `status TEXT DEFAULT 'aktif'` — kalau tidak diisi saat INSERT, otomatis terisi `'aktif'`
- `umur INTEGER CHECK (umur >= 10)` — SQLite menolak `INSERT` dengan umur di bawah 10

## Melihat Constraint Bekerja

```sql
-- Ini akan berhasil — status otomatis 'aktif', email unik
INSERT INTO anggota (id, nama, email, umur) VALUES (1, 'Dewi', 'dewi@email.com', 15);

-- Ini akan GAGAL — email sudah dipakai id 1 (melanggar UNIQUE)
INSERT INTO anggota (id, nama, email, umur) VALUES (2, 'Farhan', 'dewi@email.com', 16);

-- Ini akan GAGAL — umur di bawah 10 (melanggar CHECK)
INSERT INTO anggota (id, nama, email, umur) VALUES (3, 'Budi', 'budi@email.com', 8);
```

:::tip
Constraint adalah "penjaga gerbang" data — mereka menolak data yang melanggar aturan **sebelum** tersimpan, jadi kamu tidak perlu memeriksa validitas data secara manual di setiap query. Rancang constraint sejak awal `CREATE TABLE`, jangan menunggu data tidak valid masuk dulu baru dibersihkan.
:::

## FOREIGN KEY Sebagai Constraint

```sql
CREATE TABLE peminjaman (
  id INTEGER PRIMARY KEY,
  anggota_id INTEGER NOT NULL REFERENCES anggota(id),
  tanggal_pinjam TEXT NOT NULL
);
```

`REFERENCES anggota(id)` adalah bentuk singkat dari `FOREIGN KEY` constraint — SQLite (jika diaktifkan) akan menolak `INSERT` ke `peminjaman` dengan `anggota_id` yang tidak ada di tabel `anggota`.

## Ringkasan

| Constraint | Contoh |
|-----------|--------|
| `PRIMARY KEY` | `id INTEGER PRIMARY KEY` |
| `FOREIGN KEY` | `anggota_id INTEGER REFERENCES anggota(id)` |
| `NOT NULL` | `nama TEXT NOT NULL` |
| `UNIQUE` | `email TEXT UNIQUE` |
| `DEFAULT` | `status TEXT DEFAULT 'aktif'` |
| `CHECK` | `umur INTEGER CHECK (umur >= 10)` |

Selanjutnya: mengubah struktur tabel yang sudah ada dengan **ALTER TABLE**, dan menghapusnya sepenuhnya dengan **DROP TABLE**.
