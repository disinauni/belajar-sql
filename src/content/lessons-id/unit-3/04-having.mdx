# Menyaring Grup dengan HAVING

`WHERE` menyaring **baris mentah** sebelum dikelompokkan. Tapi bagaimana kalau kamu ingin menyaring berdasarkan **hasil agregat**-nya — misalnya "tampilkan kategori yang punya lebih dari 2 buku"? `WHERE` tidak bisa melakukan ini, karena `COUNT(*)` belum ada sebelum pengelompokan selesai. Di sinilah `HAVING` berperan.

## HAVING Dasar

```sql
SELECT kategori, COUNT(*) AS jumlah
FROM buku
GROUP BY kategori
HAVING COUNT(*) > 1;
```

Hanya kategori dengan lebih dari 1 buku yang muncul — kategori dengan tepat 1 buku (Non-Fiksi, Keuangan) tersaring keluar.

## WHERE vs HAVING — Perbedaan Mendasar

| | `WHERE` | `HAVING` |
|---|---------|----------|
| Bekerja pada | Baris mentah, sebelum dikelompokkan | Hasil kelompok, setelah agregasi |
| Bisa pakai fungsi agregat? | Tidak | Ya |
| Kapan dievaluasi | Sebelum `GROUP BY` | Sesudah `GROUP BY` |

```sql
-- ERROR secara logika: WHERE tidak bisa memakai COUNT(*)
SELECT kategori, COUNT(*) FROM buku WHERE COUNT(*) > 1 GROUP BY kategori;
```

```sql
-- BENAR: HAVING dipakai untuk menyaring hasil agregat
SELECT kategori, COUNT(*) FROM buku GROUP BY kategori HAVING COUNT(*) > 1;
```

## Menggabungkan WHERE dan HAVING

Keduanya bisa dipakai bersama — `WHERE` menyaring baris dulu, baru dikelompokkan, baru `HAVING` menyaring hasil kelompoknya:

```sql
-- Hanya buku dengan stok > 0, dikelompokkan per kategori,
-- lalu tampilkan kategori dengan rata-rata harga di atas 70000
SELECT kategori, ROUND(AVG(harga), 0) AS rata_rata
FROM buku
WHERE stok > 0
GROUP BY kategori
HAVING AVG(harga) > 70000;
```

:::tip
Cara mudah mengingat: **WHERE menyaring SEBELUM mengelompokkan** (baris individual), **HAVING menyaring SESUDAH mengelompokkan** (hasil agregat). Kalau kondisimu mengandung `COUNT`/`SUM`/`AVG`/`MIN`/`MAX`, itu harus di `HAVING`, bukan `WHERE`.
:::

## Ringkasan

| Konsep | Contoh |
|--------|--------|
| Saring hasil grup | `GROUP BY kategori HAVING COUNT(*) > 1` |
| WHERE + HAVING bersama | `WHERE stok > 0 GROUP BY kategori HAVING AVG(harga) > 70000` |
| Aturan kunci | Kondisi dengan fungsi agregat → `HAVING`, bukan `WHERE` |

Selanjutnya: menggabungkan semua klausa SELECT yang sudah kamu pelajari — `WHERE`, `GROUP BY`, `HAVING`, `ORDER BY`, `LIMIT` — dalam urutan yang benar.
